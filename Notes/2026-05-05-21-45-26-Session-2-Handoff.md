## 3. Key Decisions & Patterns

### Framework & build (unchanged from Session 1)
- **Leptos 0.7 CSR**. `Callback<T>` invoked with `.run(value)`. `spawn_local` for all async.
- **trunk** is build tool. `trunk serve` → `http://localhost:8080`.
- No JavaScript.

### TelraamAnnotation system
`TELRAAM_ANNOTATIONS` in `sources.rs` is the single developer edit point. Each entry:
```rust
(
    "telraam-XXXX",
    TelraamAnnotation {
        display_name: "Telraam: <Street> @ <Cross Street> (NDG)",
        dir_a_to_b: "A→B",   // replace with compass direction once confirmed
        dir_b_to_a: "B→A",
    },
),
```
`push_telraam_segment()` in `sources.rs` reads this annotation and emits:
1. `{source_id}-atob` (Discovered)
2. `{source_id}-btoa` (Discovered)
3. `{source_id}` / Total (TelraamExcel — this is the one that gets fetched)

`parse_telraam_excel()` in `loader.rs` checks `telraam_annotation(source_id).is_some()` before emitting directional records.

### Adding a new Telraam counter (complete recipe)
1. Add entry to `TELRAAM_ANNOTATIONS` in `sources.rs`
2. Call `push_telraam_segment(&mut out, "telraam-XXXX", LatLon{...}, earliest, file_urls, base_color_idx)` in `telraam_sources()` — use `base_color_idx` stepped by 3 from previous segment (9794=5, 10045=8, next=11)
3. Drop xlsx files in `static/data/telraam/XXXX/<year>.xlsx`

### Montreal Total source insertion
The synthetic total is inserted via `sources.insert(insert_pos, ...)` where `insert_pos` is found by `rposition` on member source IDs — ensures total appears adjacent to its siblings regardless of sort order.

### Source grouping
`DataSource.group: Option<String>` is the shared key. Set at creation time:
- Montreal directionals + total: `group = Some(make_total_id(&rue1, &rue2))`
- Telraam all three sub-sources: `group = Some(source_id)` (the base segment ID)
- Unannotated Telraam / standalone sources: `group = None`

Sidebar groups consecutive same-group items into `.source-group` div. Single-item groups render as plain `source-item`.

### Series colour computation
`series_color(modality, source_idx)` in `lib.rs`:
- Hue from modality (Bikes=350°, Peds=35°, Cars=210°, Trucks=120°, Moto=280°)
- Lightness from `LEVELS[source_idx % 8]` = `[0.65, 0.48, 0.78, 0.40, 0.84, 0.56, 0.72, 0.44]`
- `source_idx` = position in `all_srcs` signal (Telraam sources always seeded first → stable indices)

### Date range behaviour
- Initial: current year (placeholder)
- Each fetch widens: `from = min(current_from, new_earliest)`, `to = max(current_to, new_latest)`
- Presets: Summer Apr 1–Nov 15 / Winter Nov 16–Mar 31 (Montreal seasonal bike lane calendar)

### calamine API (v0.26) — unchanged from Session 1
- No `.get_string()` / `.as_f64()` — use pattern matching
- `open_workbook_from_rs::<Xlsx<_>, _>(Cursor::new(bytes))` for WASM

### Telraam Excel column names (actual headers confirmed)
- Totals: `"Bike Total"`, `"Pedestrian Total"`, `"Car Total"`, `"Large vehicle Total"`
- Directional: `"Bike (A > B)"`, `"Bike (B > A)"`, `"Pedestrian (A > B)"`, `"Pedestrian (B > A)"`, `"Car (A > B)"`, `"Car (B > A)"`, `"Heavy (A > B)"`, `"Heavy (B > A)"`
- Timestamp: `"Date and Time (Local)"` (Montreal local, DST-aware → UTC)

## 7. Important Context / Gotchas

### Leptos 0.7 API
- `Callback<T>` → `.run(value)` (not `.call()`)
- `ReadSignal<T>` and `WriteSignal<T>` are both `Copy` — can be captured in async closures directly
- `Effect::new(move |_| ...)` for reactive side-effects
- Type inference in closures sometimes needs explicit annotation (e.g., `Vec<Vec<DataSource>>` not `Vec<Vec<_>>` — caused a compile error this session)

### Telraam Excel format
- Installation ID in cell A2 of first data row (e.g., `9794`, `10045`)
- `"Large vehicle Total"` maps to `Modality::Trucks`; `"Heavy (A > B)"` is the directional equivalent
- 2024 data for segment 10045 starts 2024-09-24 (not Jan 1) — `earliest` in `push_telraam_segment` set accordingly

### Montreal CSV timestamp format
`"2025-11-04 00:00:00-05"` — 22 chars, short offset. Normalised by appending `:00` before parsing with `%:z`.

### Source colour vs. chart colour disconnect
`DataSource.color` (from `SOURCE_COLORS` palette) is shown in sidebar dots but is NOT used for chart lines. Chart lines use `series_color(modality, source_idx)` which is HSL-based. This is intentional — sidebar = location identity, chart line = semantic modality encoding. May be surprising.

### SOURCE_COLORS palette assignment
Montreal parser cycles `color_counter` for directional sources + total sources. Telraam uses hardcoded `base_color_idx` per segment (5 for 9794, 8 for 10045, next=11). These assignments are independent — potential for collisions if many sources are added. Not yet a problem.
