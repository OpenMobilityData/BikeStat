## 3. Key Decisions & Patterns

### Framework & build
- **Leptos 0.7 CSR** (client-side rendering, no SSR). Components use `#[component]`, signals via `signal()`, callbacks via `Callback::new()` called with `.run(value)` (not `.call()` — that method doesn't exist in this version).
- **`trunk`** is the build tool. `trunk serve` for dev, `trunk build --release` for production.
- **No JavaScript** — even the WASM bootstrap is injected by trunk automatically.

### Callbacks in Leptos 0.7
`Callback<T>` is invoked with `.run(value)`, not `.call(value)` or function-call syntax.

### Async loading
`wasm_bindgen_futures::spawn_local(async move { ... })` is used for all async fetches. Multiple fetches are fired concurrently at startup (Montreal CSV + each Telraam file). A `Vec<String>` signal (`load_msgs`) tracks in-flight/error messages displayed in the header.

### Granularity handling (Montreal CSV)
The Montreal CSV can contain mixed `agg_code` values (`f`=15min, `h`=hourly, `d`=daily, `m`=monthly, `y`=annual). We:
1. Accept only `"h"` and `"d"` rows
2. Per `(instance, direction)`: store hourly and daily records separately
3. When building `CountRecord`s: prefer hourly; fall back to daily if no hourly exist
This prevents double-counting when both granularities appear for the same counter/date.

### Chart series color
Series color comes from `DataSource.color` (assigned per-source), not from modality. This gives distinct colors to multiple sources of the same modality. Modality colors (defined in `Modality::color()`) are reserved for future use (e.g., legend).

### Map bounds
Computed reactively from loaded `DataSource` entries with 25% padding. Falls back to a Montreal bounding box when no sources are loaded.

### Static data files
Excel files go in `static/data/telraam/<segment_id>/<year>.xlsx`. The `index.html` includes `<link data-trunk rel="copy-dir" href="static/data" />` so trunk copies the entire `data/` tree into `dist/`.

### Location filtering (Montreal)
`MONTREAL_LOCATION_FILTER` in `sources.rs` is a `Option<&[(&str, &str)]>` whitelist of `(rue_1_substring, rue_2_substring)` pairs matched case-insensitively. `None` = include all. Currently set to Bourret/Décarie and Girouard/Terrebonne. Uses `"carie"` to match `"Décarie"` without accent sensitivity.

## 7. Important Context / Gotchas

### Leptos 0.7 API notes
- `Callback<T>` → call with `.run(value)` not `.call(value)`
- SVG `NodeRef` for `<svg>` elements doesn't exist in Leptos 0.7 — just omit `node_ref`
- `Memo<T>` requires `T: PartialEq` — `Vec<Series>` works because `Series` derives `PartialEq`
- `Effect::new(move |_| ...)` is the correct way to react to signal changes and update another signal
- In Leptos 0.7, `spawn_local` is re-exported but cleanest to import from `wasm_bindgen_futures`

### calamine API (v0.26)
- `Data::get_string()` and `Data::as_f64()` do NOT exist — must use pattern matching
- Use a free function `fn cell_str(c: &Data) -> Option<&str>` (not a closure, due to lifetime constraints) and `fn cell_f64(c: &Data) -> f64` with explicit match arms
- `open_workbook_from_rs::<Xlsx<_>, _>(Cursor::new(bytes))` is the WASM-compatible entry point

### Trunk asset handling
- CSS: `<link data-trunk rel="css" href="...">` (not `rel="stylesheet"`)
- Icon: `<link data-trunk rel="icon" ...>`
- Directory copy: `<link data-trunk rel="copy-dir" href="static/data" />`

### Montreal CSV encoding
The CSV is UTF-8. Apparent garbling in some terminals is a display artifact — parse as UTF-8 normally. The `"Décarie"` filter uses `"carie"` substring to avoid any residual accent issues.

### Montreal CSV timestamp format
`"2025-11-04 00:00:00-05"` — 22 chars. The offset is short (`-05`), not the standard `±HH:MM`. We normalise by appending `:00` before passing to chrono's `%:z` format specifier.

### WASM binary size
Dev build: ~4.6 MB WASM (chrono-tz timezone database is large). Release build with LTO will be significantly smaller. Acceptable for local dev; optimise before deploying to lighttpd.

### Data file locations
Telraam Excel files are **manually downloaded** from the Telraam web UI (no automation possible). Historical data only. Ongoing updates must come from the Telraam API (not yet implemented). Files go in `static/data/telraam/<installation_id>/<year>.xlsx`.

### Montreal CSV — direction column
`direction` in the Montreal CSV is the direction of cyclist travel (e.g., "Ouest", "Est"). Not the same as Telraam's A→B / B→A convention. Each physical Montreal counter typically covers one direction only, resulting in separate instance IDs.
