## 1. Current Task & Objective

Building **BikeStat** (formerly NoBikes), a Rust/WebAssembly web application that aggregates and displays traffic count data (bicycles, pedestrians, cars, trucks) from multiple open data sources. Hosted on a `lighttpd` server on a remote Linux machine. Local git repo exists; no GitHub remote yet.

**Core UI concept:** Single chart view (counts vs. time) with sidebar controls for selecting data sources/locations, time resolution, time window, and modalities, plus a map showing available counting stations.

**Constraint:** No hand-written JavaScript — all UI logic in Rust/WASM.

## 3. Key Decisions & Patterns

### Map rendering: HTML/CSS over SVG
SVG was abandoned for the map because Leptos 0.7 appears to mishandle camelCase SVG attributes — `preserveAspectRatio="xMidYMid meet"` was being ignored, causing tiles and labels to stretch horizontally to fill wide containers. The HTML/CSS approach is more predictable: `position: absolute; left: calc(50% + Xpx); top: calc(50% + Ypx)` for everything, no aspect-ratio gymnastics. Chart still uses SVG (its narrower aspect makes the issue invisible there).

### Map: integer tile zoom + CSS transform scale
Web map tiles are only available at integer zoom levels, but for our fixed-height viewport (220px) the integer steps are coarse — markers either fit comfortably with lots of margin (z=12) or overflow vertically (z=13). Solution: pick the integer zoom that fits, then apply a CSS `transform: scale()` on the wrapper to fill the viewport at the desired `FIT_FRACTION`. Tiles stay at native tile resolution, scaled in CSS; @2x tiles keep things crisp.

### Marker dedupe via `group` key + total convention
Sources have an optional `group: Option<String>` set at creation time. By convention, the total source's `id` equals the group key (e.g., `make_total_id()` for VdM, the bare segment id for Telraam). The map filters via `s.id == group`, so each location group surfaces exactly one marker — the total. Clicking selects the total; sub-sources can still be added manually from the sidebar.

### Edge-aware label flipping
Labels are positioned 12px below the dot via `top: 12px` on `.marker-label`. When the dot is within 36px of the container bottom, the marker gets a `label-above` class which swaps to `bottom: 12px` (anchors the label above the dot's geometric position). The threshold accounts for label height (~14px) + 12px gap + small safety margin.

### Series stats in legend
Computed inline in the legend rendering (not in `Series` struct) from `ser.points` — this means stats automatically reflect any aggregation/filtering applied upstream. Resolution change (hour/day/week) changes `max` (because bucket sizes change) but not `total` (regrouping preserves sum).

### Telraam annotations system (unchanged from session 2)
`TELRAAM_ANNOTATIONS` slice in `sources.rs` is the single source of truth for per-segment metadata. Adding a new counter:
1. Add entry to `TELRAAM_ANNOTATIONS`
2. Call `push_telraam_segment()` in `telraam_sources()` with a `base_color_idx` stepped by 3 from the previous (current: 9794=5, 10045=8, next=11)
3. Drop xlsx files in `static/data/telraam/<id>/<year>.xlsx`

### Leptos 0.7 reminders (unchanged)
- `Callback<T>` invoked with `.run(value)`
- `spawn_local` for async
- `ReadSignal<T>` and `WriteSignal<T>` are `Copy`
- SVG attribute case-handling is unreliable — prefer HTML/CSS where possible

## 7. Important Context / Gotchas

### Leptos 0.7 SVG attribute issue
The map originally used SVG with `viewBox` and `preserveAspectRatio="xMidYMid meet"`, but Leptos 0.7 appears to drop or mishandle camelCase SVG attributes — the result was full-width tile rendering with horizontally squished labels. The fix was to switch the map to HTML/CSS entirely. The chart still uses SVG and works fine, possibly because the chart's aspect ratio is closer to its container's aspect ratio so the misbehaviour is invisible. **If you ever see SVG content stretching weirdly, suspect this issue and consider HTML/CSS as a workaround.**

### Map fit math
`pick_zoom` uses **unpadded** marker bbox (no breathing-room padding). The breathing room comes from `FIT_FRACTION < 1.0` which constrains the post-scale marker span to that fraction of the viewport. So if you want more zoom, lower `FIT_FRACTION`; if you want more margin, raise it.

### CSS transform-origin and scaled positioning
`.map-content` uses `position: absolute; inset: 0` which makes it the same size as `.map-container`. With default `transform-origin: 50% 50%` and `transform: scale(s)`, child positions like `left: calc(50% + Xpx)` get scaled around the centre — so the offset `Xpx` becomes an effective `Xpx * s` on screen. Markers' `dot_screen_y = VIEWPORT_H/2 + off_y * scale` is the actual rendered y position used for the edge-flip threshold.

### CartoDB tile licensing
`dark_nolabels` is free for non-commercial use with mandatory attribution ("© OpenStreetMap © CARTO" — currently in bottom-right of the map). For commercial deployment we'd need a CARTO account. OSM standard tiles also work but clash with the dark theme.

### Cargo.lock is gitignored
Per `.gitignore`, `Cargo.lock` is not tracked. This is unusual for binary applications (lock files are normally tracked) but matches the existing setup. Don't worry about Cargo.lock not appearing in `git status`.

### Telraam Excel format (unchanged from session 2)
- Installation ID in cell A2 of first data row
- `"Large vehicle Total"` → `Modality::Trucks`; `"Heavy (A > B)"` → directional Trucks
- 2024 data for segment 10045 starts 2024-09-24 (not Jan 1)
- Timestamp column: `"Date and Time (Local)"` (Montreal local, DST-aware → UTC via chrono-tz)

### Montreal CSV timestamp format (unchanged)
`"2025-11-04 00:00:00-05"` — 22 chars, short offset. Normalised by appending `:00` before parsing with `%:z`.

### Source colour vs. chart line colour disconnect (unchanged from session 2)
`DataSource.color` (from `SOURCE_COLORS` palette) is shown in sidebar dots but is NOT used for chart lines. Chart lines use `series_color(modality, source_idx)` which is HSL-based (hue=modality, lightness=source index). Intentional — sidebar = location identity, chart line = semantic modality encoding.
